# STM32、Qt 服务端、Qt 客户端通信协议说明

## 1. 系统整体流程

```text
STM32 + ESP8266
        │ MQTT
        ▼
EMQX Broker（broker.emqx.io:1883）
        │ MQTT
        ▼
Qt 服务端
   ├── SQLite 数据库
   └── TCP 6666
        │ TCP
        ▼
Qt 客户端
```

数据采集方向：

```text
STM32 → ESP8266 → MQTT → EMQX → Qt 服务端 → SQLite
                                             ↓ TCP
                                         Qt 客户端
```

控制命令方向：

```text
Qt 客户端 → TCP → Qt 服务端 → MQTT → EMQX → ESP8266 → STM32
```

注意：STM32 不连接 Qt 服务端的 TCP `6666` 端口。STM32 通过 MQTT 与服务端间接通信。

## 2. 网络配置

### MQTT

```text
Broker：broker.emqx.io
端口：1883
协议：MQTT over TCP
```

Qt 服务端和 ESP8266 都要连接这个 Broker。MQTT Client ID 必须唯一，例如：

```text
Qt 服务端：qt_server_001
STM32设备：esp_stm32_001
```

### TCP

Qt 服务端监听：

```text
端口：6666
```

客户端和服务端在同一台电脑时：

```text
127.0.0.1:6666
```

客户端和服务端在两台电脑时，客户端填写服务端电脑的局域网 IPv4 地址，例如：

```text
10.94.77.34:6666
```

## 3. MQTT 主题

设备编号以 `stm32_001` 为例。

| 用途 | 方向 | 主题 |
|---|---|---|
| 服务端订阅所有设备采集数据 | 设备 → 服务端 | `shengtu/program3/device/+/telemetry` |
| STM32_001 发布采集数据 | STM32 → Broker | `shengtu/program3/device/stm32_001/telemetry` |
| STM32_001 订阅控制命令 | 服务端 → STM32 | `shengtu/program3/device/stm32_001/command` |
| STM32_002 发布采集数据 | STM32 → Broker | `shengtu/program3/device/stm32_002/telemetry` |
| STM32_002 订阅控制命令 | 服务端 → STM32 | `shengtu/program3/device/stm32_002/command` |

`+` 是 MQTT 单层通配符，只能由订阅使用，不能用于发布主题。

## 4. 采集数据：STM32 → 服务端

### MQTT 发布主题

```text
shengtu/program3/device/stm32_001/telemetry
```

### MQTT Payload

```json
{
  "device_id": "stm32_001",
  "seq": 4,
  "timestamp": 1788940800000,
  "temperature": 25.6,
  "humidity": 48.2
}
```

字段说明：

| 字段 | 类型 | 含义 |
|---|---|---|
| `device_id` | 字符串 | 设备编号，必须存在 |
| `seq` | 整数 | 数据序号，同一设备应递增 |
| `timestamp` | 整数 | 设备时间戳，建议使用毫秒；没有时服务端使用接收时间 |
| `temperature` | 小数 | 温度 |
| `humidity` | 小数 | 湿度 |

服务端收到后会：

```text
MQTT接收 → JSON解析 → 写入 telemetry 表 → TCP转发给客户端
```

SQLite 使用 `device_id + seq` 防止 QoS 1 重发产生重复数据。因此重新测试时要修改 `seq`。

## 5. 实时数据：服务端 → 客户端

服务端通过 TCP 发送一行 JSON：

```json
{
  "type": "telemetry",
  "topic": "shengtu/program3/device/stm32_001/telemetry",
  "data": {
    "device_id": "stm32_001",
    "seq": 4,
    "temperature": 25.6,
    "humidity": 48.2
  }
}
```

每条 TCP JSON 后面追加一个换行符 `\n`，客户端按换行符拆分消息。

## 6. 控制命令：客户端 → 服务端 → STM32

### 6.1 客户端发给服务端的 TCP JSON

打开继电器：

```json
{
  "type": "command",
  "device_id": "stm32_001",
  "relay": 1
}
```

关闭继电器：

```json
{
  "type": "command",
  "device_id": "stm32_001",
  "relay": 0
}
```

### 6.2 服务端发布给 STM32 的 MQTT

主题：

```text
shengtu/program3/device/stm32_001/command
```

Payload：

```json
{"relay":1}
```

服务端会删除 `type` 和 `device_id`，因为这两个字段只用于服务端路由设备。

### 6.3 服务端返回客户端的 TCP 结果

成功：

```json
{
  "type": "command_result",
  "device_id": "stm32_001",
  "success": true,
  "message": "命令已发布到 MQTT"
}
```

失败：

```json
{
  "type": "command_result",
  "device_id": "stm32_001",
  "success": false,
  "message": "命令发布失败"
}
```

当前协议建议统一使用 `relay`。如果 STM32 代码仍然解析 `duty`，需要后续统一字段，不能一边使用 `relay`、另一边使用 `duty`。

## 7. 历史查询：客户端 ↔ 服务端

### 7.1 客户端请求

客户端通过 TCP 发送：

```json
{
  "type": "history_query",
  "device_id": "stm32_001",
  "start_time": 0,
  "end_time": 9999999999999
}
```

### 7.2 服务端返回

```json
{
  "type": "history_result",
  "success": true,
  "device_id": "stm32_001",
  "data": [
    {
      "device_id": "stm32_001",
      "seq": 3,
      "timestamp": 1788940700000,
      "temperature": 25.4,
      "humidity": 48.0,
      "received_at": "2026-09-11 12:00:00"
    },
    {
      "device_id": "stm32_001",
      "seq": 4,
      "timestamp": 1788940800000,
      "temperature": 25.6,
      "humidity": 48.2,
      "received_at": "2026-09-11 12:05:00"
    }
  ]
}
```

## 8. 数据格式注意事项

1. JSON 中下划线直接写 `_`，不要写成 `\_`：

   ```text
   device_id
   stm32_001
   ```

2. JSON 必须使用英文双引号 `"`，不能使用中文引号。
3. MQTT Payload 是 JSON；MQTT 主题是普通字符串，不是 JSON。
4. `hello` 只能用来测试 MQTT 是否连通，不符合服务端入库格式。
5. TCP 一条消息使用一行 JSON，末尾以 `\n` 结束。
6. MQTT 不要求设备、服务端和客户端处于同一个局域网，只要都能连接 `broker.emqx.io`；客户端和服务端使用 TCP 时则必须能访问服务端的 `6666` 端口。

## 9. 当前测试顺序

### 9.1 测试采集数据

1. 启动 Qt 服务端，确认 MQTT 已连接、订阅成功。
2. MQTTX 订阅：

   ```text
   shengtu/program3/device/stm32_001/telemetry
   ```

3. 用 ESP8266 手动发布一条 JSON，或让 STM32 发布。
4. 确认 MQTTX 收到 JSON。
5. 确认 Qt 服务端显示 MQTT 收到、SQLite 写入成功。
6. 确认 Qt 客户端显示实时数据。

### 9.2 测试控制命令

1. MQTTX 或 STM32 订阅：

   ```text
   shengtu/program3/device/stm32_001/command
   ```

2. Qt 客户端发送：

   ```json
   {"type":"command","device_id":"stm32_001","relay":1}
   ```

3. 确认服务端显示 MQTT 发布成功。
4. 确认 MQTTX/STM32 收到：

   ```json
   {"relay":1}
   ```

### 9.3 测试历史查询

客户端发送：

```json
{"type":"history_query","device_id":"stm32_001","start_time":0,"end_time":9999999999999}
```

确认服务端显示返回数据条数，客户端显示历史记录。
